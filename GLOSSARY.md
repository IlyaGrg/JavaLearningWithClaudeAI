# Java Backend Glossary

Канонические термины курса. Уроки и ревью используют именно эти слова.

## Java Core

**Метод**:
Именованный блок кода внутри класса с объявленными типами параметров и типом результата.
_Avoid_: функция (термин из Python), процедура

**Сигнатура метода**:
Имя метода плюс типы его параметров. Тип результата в сигнатуру не входит.

**Перегрузка (overloading)**:
Несколько методов с одним именем и разными сигнатурами в одном классе.
_Avoid_: переопределение (это другое понятие, будет в уроке про наследование)

**Ссылка**:
Значение переменной ссылочного типа (массив, `ArrayList`, объект), указывающее на объект в памяти.
_Avoid_: указатель, «адрес в памяти» (хеш-код в `[I@1b6d3586` не адрес)

**Передача по значению**:
Единственный способ передачи аргументов в Java: метод получает копию значения переменной. Для ссылочных типов копируется ссылка, а объект остаётся общим.
_Avoid_: «объекты передаются по ссылке»

**Инкапсуляция**:
Поля объекта закрыты (`private`), и менять их можно только через методы самого класса, которые проверяют правила.
_Avoid_: «сокрытие» как синоним: прячем ради защиты правил, а не ради секретности

**Модификатор доступа**:
Слово перед полем, методом или классом (`private`, `public`, `protected` или его отсутствие), которое определяет, из какого кода к нему можно обратиться.

**Геттер / сеттер**:
Метод, возвращающий значение поля (`getX()`, для `boolean` — `isX()`), и метод, меняющий его с проверкой (`setX(...)`). Сеттер пишут только для полей, которые действительно должны меняться.

**Инвариант**:
Правило, которое должно выполняться для объекта всегда, например «баланс ≥ 0». Конструктор и методы обязаны его сохранять.

**Исключение**:
Объект-сигнал об ошибке, который бросается через `throw` и прерывает выполнение метода. Пока знаем одно: `IllegalArgumentException` — «передали недопустимый аргумент».
_Avoid_: «ошибка» в смысле ошибки компиляции: исключение возникает во время работы программы

**Стек вызовов (call stack)**:
Цепочка методов, которые сейчас выполняются: каждый вызов кладётся сверху на вызвавший его метод. Строки `at ...` в сообщении об исключении — снимок этого стека (stack trace).

**throw / throws**:
`throw` — действие в теле метода: бросить исключение сейчас. `throws` — объявление в сигнатуре: «метод может бросить такое исключение».
_Avoid_: путать местами — `throws new X()` в теле не компилируется

**Checked / unchecked исключение**:
Checked (потомки `Exception`, кроме ветки `RuntimeException`) компилятор требует поймать или объявить в `throws`. Unchecked (`RuntimeException` и потомки) не проверяет. Свои исключения в курсе пишем unchecked.

**Компиляция / выполнение**:
Компиляция (`javac`) проверяет код и превращает его в `.class`, ничего не запуская. Выполнение (`java`) запускает программу и даёт вывод и исключения.
_Avoid_: «компилятор вывел» о выводе работающей программы

**Наследование**:
Класс-потомок (`extends`) получает поля и методы класса-родителя и добавляет своё. Уместно, только если «потомок — разновидность родителя». У класса один родитель; без `extends` родитель — `Object`.
_Avoid_: наследование ради переиспользования пары методов — для этого поле (композиция)

**Переопределение (overriding)**:
Метод потомка с той же сигнатурой, что у родителя. Заменяет родительскую версию целиком; чтобы выполнить и её, вызывают `super.метод()`. Помечается `@Override`.
_Avoid_: путать с перегрузкой (разные параметры, один класс)

**super**:
`super(...)` — вызов конструктора родителя, первой строкой конструктора (без него Java подставит `super()`). `super.метод()` — вызов родительской версии переопределённого метода.

**Полиморфизм**:
В переменной типа родителя может лежать объект-потомок. Какие методы можно вызвать — решает тип переменной (компилятор); какая версия выполнится — тип объекта (при выполнении).

**Интерфейс**:
Договор о методах (`interface`): объявляет методы без тела, которые обязан иметь каждый реализующий класс (`implements`). Объект интерфейса создать нельзя, а переменную его типа — можно. Класс может реализовать сколько угодно интерфейсов.
_Avoid_: «интерфейс» в смысле UI; префикс `I` в имени (`INotifier`)

**Внедрение зависимости (dependency injection)**:
Объект не создаёт то, что ему нужно, а получает это снаружи, обычно через конструктор, по типу интерфейса: `new TransferService(new SmsNotifier())`. В Spring объекты передаёт сам фреймворк.

**Фейк (fake)**:
Упрощённая реализация интерфейса для проверок: ничего не делает по-настоящему, только запоминает вызовы, чтобы тест мог спросить, что произошло.

**Тест (самопроверка)**:
Код, который сравнивает поведение программы с требованием и сам печатает результат («ОК» / «ОШИБКА»), без разглядывания вывода. Пишется по заданию, а не по тому, что программа уже выводит. Ловит регрессии — поломки при будущих изменениях.

**equals / ==**:
`==` на объектах — тот же самый объект (ссылки равны), как `is` в Python. `equals` — равны по смыслу, как `==` в Python. Примитивы сравнивают через `==`, объекты (`String`, `Integer`, свои классы) — через `equals`.

**hashCode**:
Число, по которому `HashMap`/`HashSet` выбирают корзину; внутри корзины сравнивают через `equals`. Договор: равные по `equals` объекты обязаны иметь равный `hashCode`. Переопределяется только вместе с `equals`, по тем же полям.

**Объект-значение / сущность**:
Объект-значение определяется данными (`Money`, `AccountNumber`, `String`) — `equals` по полям. Сущность определяется идентичностью (счёт, клиент) — `equals` по ссылке или по уникальному id.

**Приведение типа (cast)**:
`(Money) o` — смотреть на объект через переменную более конкретного типа. Объект не меняется. Делать только после проверки, что объект действительно этого типа.

**Generics (обобщённые типы)**:
Класс, интерфейс или метод с параметром типа: `List<E>`, `Repository<T, ID>`. Один код работает с разными типами, а компилятор проверяет типы при компиляции, без приведений и `ClassCastException`.

**Параметр типа / аргумент типа**:
Параметр — имя-заглушка в объявлении: `T` в `class Box<T>`. Аргумент — конкретный тип при использовании: `String` в `Box<String>`. Аргументом может быть только ссылочный тип (`Integer`, не `int`).

**Ограничение типа (bound)**:
`<T extends Comparable<T>>` — `T` может быть только типом, который умеет сравниваться. Даёт право вызывать у `T` методы ограничения (`compareTo`). `extends` здесь значит и «наследует», и «реализует».

**Сырой тип (raw type)**:
Generic-тип без угловых скобок: `List` вместо `List<String>`. Компилируется с предупреждением `unchecked`, проверка типов теряется, ошибка всплывает при выполнении. Не использовать.

**Репозиторий**:
Объект, который хранит сущности и ищет их по id: `save`, `findById`, `findAll`, `deleteById`. Код банка работает с интерфейсом и не знает, где лежат данные: в `Map` или в базе. В Spring Data — `CrudRepository<T, ID>`.
