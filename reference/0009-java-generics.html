Generics

Шпаргалка к уроку 0009.

Зачем

Проверка типов при компиляции вместо ClassCastException при выполнении, и никаких приведений при чтении.

Generic-класс

public class Pair<A, B> {          // параметры типа
    private A first;
    private B second;

    public Pair(A first, B second) { ... }   // у конструктора скобок нет
    public A getFirst() { return first; }
}

Pair<String, Integer> p = new Pair<>("Чай", 250);   // аргументы типа, ромб <>

Generic-интерфейс

public interface Repository<T, ID> { T findById(ID id); }

class InMemoryRepository<T, ID> implements Repository<T, ID> { ... }   // остаётся generic
class BankAccount implements Comparable<BankAccount> { ... }          // подставляет тип

Generic-метод

public static <T> T firstOrThrow(List<T> list) { ... }
String s = firstOrThrow(names);           // T выводится сам: String

Ограничение

public static <T extends Comparable<T>> T max(List<T> list) {
    ...  item.compareTo(best)  ...        // можно: T точно сравним
}

extends в угловых скобках — и «наследует класс», и «реализует интерфейс».

Wildcard (читать, не писать)

List<? extends Number> — список чего-то, что является Number. List<Integer> — это не List<Number>.
