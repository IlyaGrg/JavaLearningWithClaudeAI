Git-ветки

Шпаргалка к уроку 0010.

Модель

Ветка — подвижный указатель на коммит. HEAD — где я сейчас (текущая ветка). Коммит сдвигает указатель текущей ветки.

Команды

КомандаЧто делает
git branchсписок веток, * — текущая
git switch -c имясоздать ветку от текущего коммита и перейти
git switch имяперейти; файлы в папке заменятся снимком ветки
git merge имявлить ветку имя в текущую
git merge --abortотменить слияние с конфликтом
git branch -d имяудалить слитую ветку
git branch -D имяудалить в любом случае (коммиты пропадут)
git log --oneline --graph --allграф всех веток
git push -u origin имяотправить ветку на GitHub (первый раз)
git restore файлоткатить незакоммиченные изменения файла

git checkout -b имя — старый вариант git switch -c имя.

Два вида слияния

fast-forward:   в main не было новых коммитов → main просто сдвигается
                «Fast-forward»

коммит слияния: обе ветки ушли вперёд → новый коммит с двумя родителями
                «Merge made by the 'ort' strategy.»

Рабочий цикл

git switch main && git status        # чисто?
git switch -c feature/задача
# код → проверки ОК → git commit
git switch main
git merge feature/задача
git branch -d feature/задача
git push

Эксперимент

git switch -c experiment/что-ломаю
# сломать → запустить → записать → git commit -am "..."
git switch main
git branch -D experiment/что-ломаю

-d неслитой веткиerror: the branch '…' is not fully merged
обе ветки меняли одну строкуКОНФЛИКТ (содержимое), маркеры <<<<<<< HEAD / ======= / >>>>>>>
открылся vim при mergeEsc, :wq, Enter

Имена

feature/… — новое, fix/… — исправление, refactor/… — переделка без смены поведения, experiment/… — на выброс.
