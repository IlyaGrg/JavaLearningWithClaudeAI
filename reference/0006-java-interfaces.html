Объявление и реализация

public interface Notifier {
    void send(String recipient, String message);   // без тела, неявно public
}

public class SmsNotifier implements Notifier {
    @Override
    public void send(String recipient, String message) {   // обязательно public
        System.out.println("[SMS → " + recipient + "] " + message);
    }
}

Интерфейс как тип

Notifier n = new SmsNotifier();          // ✓ переменная типа интерфейса
Notifier x = new Notifier();             // ✗ объект интерфейса нельзя
ArrayList<Notifier> all = ...;          // разные классы в одном списке

Правила как у наследования: методы — по типу переменной, версия — по объекту.

Зависимость через конструктор

public class OrderService {
    private Notifier notifier;                     // тип интерфейса

    public OrderService(Notifier notifier) {       // передают снаружи
        this.notifier = notifier;
    }
}

new OrderService(new SmsNotifier());           // настоящая реализация
new OrderService(new FakeNotifier());          // фейк для проверки

Внедрение зависимости (dependency injection). В Spring объект в конструктор передаёт сам фреймворк.

public class Product implements Comparable<Product> {

    public int compareTo(Product other) {

Синтаксис объявления класса

class A extends Parent implements I1, I2 { }   // сначала extends, потом implements
interface I3 extends I1 { }                    // интерфейс расширяет интерфейс

Родитель реализует интерфейс → потомки реализуют его автоматически.
