Исключения

Шпаргалка к уроку 0004.

try / catch

try {
    tea.sell(amount);                         // может бросить
    System.out.println("Продано");            // только если не бросило
} catch (OutOfStockException e) {             // частный тип — выше
    System.out.println(e.getMessage());
} catch (IllegalArgumentException e) {        // общий — ниже
    System.out.println("Ошибка: " + e.getMessage());
}
System.out.println("дальше");                 // выполняется в обоих случаях

Поток выполнения

  1. Исключение обрывает каждый метод по пути вверх по стеку, пока не попадёт в try с подходящим catch.
  2. Строки try после места броска не выполняются. Назад в try не возвращаемся.
  3. Срабатывает первый подходящий catch сверху. После него — код за всей конструкцией.
  4. Никто не поймал → программа падает и печатает стек.

Дерево

Throwable
├── Error                         не ловить
└── Exception                     checked (кроме ветки ниже)
    ├── IOException               checked
    └── RuntimeException          unchecked
        ├── IllegalArgumentException
        │   └── NumberFormatException
        └── NullPointerException

catch (X e) ловит X и всех потомков. Порядок catch: от частного к общему.

Своё исключение

public class OutOfStockException extends RuntimeException {
    public OutOfStockException(String message) {
        super(message);              // первой строкой; сообщение хранит родитель
    }
}

Методы исключения

e.getMessage()текст, переданный в конструктор
e.printStackTrace()тип, сообщение и строки at — для отладки
throw e;внутри catch — бросить дальше

Не делай

  • Пустой catch { } — ошибка исчезает молча.
  • catch (Exception e) «на всякий случай» — заодно ловит баги.
  • Исключения вместо обычного if для нормальных вариантов.
  • Ловить NullPointerException — его предотвращают проверкой на null.
