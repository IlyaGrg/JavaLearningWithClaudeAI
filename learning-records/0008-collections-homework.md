# Коллекции: Map/Set/List применяет верно, но банк отдаёт свою Map наружу

В домашке 0007 Илья сам выбрал коллекции правильно: `Map<String, BankAccount>` для поиска по номеру, `Set<String>` для уникальных владельцев, `Map<String, List<BankAccount>>` для группировки. Отсутствующий номер ловит своей проверкой с понятным исключением, без NPE. Обход через `entrySet`. Метод `check(name, condition)` написал, три проверки проходят. **Предсказание с `HashSet` верное и сделано до запуска**: 2 счёта / 1 строка, с догадкой «считает объекты разными, хотя поля одинаковые» — хороший вход в урок 8. `ConcurrentModificationException` воспроизвёл и записал стек.

**Evidence**: `src/lesson0007/`, коммиты 2cec2b6, d4fce8d плюс незакоммиченные `Main.java` и `Bank.java`; ревью 2026-10-15, JDK 21.

**Implications**:
- **Пробел (главный)**: `Bank` принимает `Map` в конструкторе и хранит **ту же ссылку**. `Main` наполняет её через `accounts.put`, в обход `openAccount`. Проверено: `m.put("001", мошенник)` снаружи молча подменяет счёт, `m.clear()` обнуляет банк. Алиасинг (урок 2) и инкапсуляция (урок 3) не перенесены на поле-коллекцию. Вопрос в задании «почему опасно вернуть наружу поле» в обратную сторону (принять снаружи) не распознан. `openAccount` при этом ни разу не вызван, поэтому проверка 4 (дубликат номера) не написана и не могла быть написана.
- `check` используется как `if (условие) { check(name, true) } else { check(name, false) }`. Смысл параметра `boolean condition` (передать само выражение) не понят. Проверка 5 (несуществующий номер) печатает текст, а не вызывает `check`.
- Группировки сделаны вложенными циклами «по владельцам × по счетам» вместо одного прохода с `getOrDefault` / «если списка нет — создать». Работает, но приём «подсчёт» из урока не применён.
- Эксперимент 4.2 сделан на `new ArrayList<>(List.of(...))`, поэтому ошибки нет. Сам заметил «видимо что-то неправильно», но не разобрался. 4.3 (NPE от `get`) не сделан.
- Мелочи: `openAccount` не проверяет `account == null` (проверено: потом NPE в `totalBalance`); `checkingNumber` — `public`-помощник; у `findAccount` нет модификатора доступа; имена `DuplicateAccountException` / `AccountNotFoundException` неясны; имя метода `accountByOwner` вместо `accountsByOwner`; README не обновлён.
