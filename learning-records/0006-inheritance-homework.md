# Наследование: полиморфизм предсказал верно, но переопределение «заменяет», а не «дополняет»

В домашке 0005 Илья сам написал `SavingsAccount extends BankAccount`: `super(owner, balance)` первой строкой, проверки своих полей после него. `addInterest` пополняет счёт через унаследованный `deposit`, потому что `balance` — `private`. `toString` использует `super.toString()`. Сделал своё исключение с данными (`ExceedingTheLimit`, позже переименовано в `WithdrawalLimitExceededException`), по образцу урока 4. **Предсказание с `transferTo` верное**: перевод упадёт, потому что внутри вызовется переопределённый `withdraw`. Подтвердил стеком. Ошибку `cannot find symbol` у `accounts.get(i).addInterest()` объяснил правилом «методы определяет тип переменной».

**Evidence**: `src/lesson0005/`, коммит 0900020; ревью 2026-10-12, JDK 21 и граничные случаи.

**Implications**:
- **Пробел (главный)**: переопределённый `withdraw` проверяет только лимит и не вызывает `super.withdraw(amount)`. Снятие в пределах лимита **ничего не списывает**, отрицательная сумма и сумма больше баланса проходят молча. `transferTo(other, 2000)` создаёт деньги из ничего: получатель +2000, отправитель без изменений — тот самый «дюп» из урока 3. Не заметил, потому что цикл снятия в `Main` ничего не печатает (шаг 3.3 требовал печати). Модель «переопределение заменяет метод целиком, родительский код больше не выполняется сам» не сформирована.
- В обосновании предсказания ссылается на тип переменной (`SavingsAccount`), хотя версию выбирает объект (`this` внутри `transferTo`). Проверить вопросом: изменится ли результат при `BankAccount savings = new SavingsAccount(...)`.
- Эксперимент 5.3 (опечатка без `@Override`): ответ «Лимит тот же» неверен или непонятен. На деле вызывается родительский `withdraw`, и лимит перестаёт работать. Наблюдать не мог, потому что ничего не печатал.
- Объяснение ошибки без `super(...)` расплывчатое («не осуществляется конструктор»). Механизм неявного `super()` не назван.
- Мелочи: имя исключения без суффикса `Exception`; лишний `import` того же пакета; сообщение «неотрицательным» при проверке `<= 0`; `get(1)` — обычный счёт, а не накопительный; нет комментария, почему выбрано своё исключение.

**Update (ревью 2026-10-13, не закоммичено)**: главный баг исправлен: `super.withdraw(amount)` после проверки лимита. Проверено: снятие в лимите списывает, «больше баланса» и «отрицательное» отсекаются проверками родителя, перевод больше не создаёт деньги. Эксперимент 5.3 переосмыслен верно: вызывается родительская версия, лимит не работает. Объяснение 5.1 дословно взято из урока; механизм неявного `super()` записан, но своими словами не сформулирован. Оба правила полиморфизма сформулировал своими словами: «тип переменной — какие методы, тип объекта — какая версия». Причина своего исключения — «понятнее и точнее».
