Урок 0013 · Java Core · ~90 минут + домашка

enum, record, Optional: типы, которые говорят правду

После этого урока ты сможешь заменить строки-константы перечислением, объект-значение — записью в одну строку, а «может вернуть null» — честным Optional, как в Spring Data.

Зачем этот урок для backend. В Spring-проекте статусы заказов и роли пользователей — это enum. Объекты, которые приходят в REST API и уходят из него (DTO), почти всегда record. А CrudRepository.findById в Spring Data возвращает Optional<T> — сегодня твой репозиторий станет таким же.

Разминка

1. Урок 12, хвост: что напечатает этот код? Stream<String> s = List.of("a", "b").stream().filter(x -> { System.out.println("проверяю " + x); return true; }); — а если потом вызвать s.count()?

Сначала — ничего: стрим ленивый, filter только описал участок конвейера. После count() — «проверяю a», «проверяю b». Это эксперимент 6.3, который ты не досмотрел: в домашке он первым шагом.

2. Урок 8: какие пять строк ты писал в каждом equals?

this == o → null и getClass → приведение типа → сравнение полей. Плюс hashCode через Objects.hash по тем же полям. Сегодня Java напишет это за тебя.

3. Урок 9: твой findById не нашёл — что он делает? А HashMap.get?

Твой — бросает EntityNotFoundByIdException. HashMap.get — молча возвращает null (урок 7, NPE в totalBalance). Ни то, ни другое не видно по сигнатуре метода. Optional делает «может не найтись» частью типа.

1. enum: конечный список вариантов

Валюты у тебя сейчас — строки "RUB", "USD". Строку можно написать с опечаткой ("RUR", "usd"), и компилятор промолчит. Когда вариантов конечное число, их объявляют перечислением (Oracle: Enum Types):

public enum Currency {
    RUB, USD, EUR
}

Currency c = Currency.USD;      // только эти три значения, опечатка не скомпилируется

enum — это класс, у которого ровно столько объектов, сколько констант, и все они созданы заранее. Поэтому сравнивать их можно через ==: Currency.RUB == Currency.valueOf("RUB") → true. Исключение из правила урока 8 — ведь второго объекта RUB просто не существует.

Поля, конструктор, методы

public enum Currency {
    RUB("Российский рубль"),
    USD("Доллар США"),
    EUR("Евро");

    private final String displayName;

    Currency(String displayName) {          // конструктор всегда private
        this.displayName = displayName;
    }

    public String getDisplayName() {
        return displayName;
    }
}

Currency.USD.getDisplayName();   // "Доллар США"

Твой Repository<String, String> «код → название» из урока 9 — это и есть такое перечисление, только без защиты от опечаток.

Встроенные методы

Currency.values()все константы: [RUB, USD, EUR]
Currency.valueOf("EUR")константа по имени. Нет такой — IllegalArgumentException: No enum constant …Currency.JPY
c.name(), toString()"USD"
c.ordinal()номер по порядку (0, 1, 2) — не используй для логики: переставишь константы — всё сломается

switch-выражение

С Java 14 switch умеет возвращать значение (Oracle: Switch Expressions):

String symbol = switch (currency) {
    case RUB -> "₽";
    case USD -> "$";
    case EUR -> "€";
};

Стрелка вместо двоеточия — и не нужен break. А главное: если ты добавишь в enum константу CNY и забудешь про неё здесь, компилятор остановит (проверено на JDK 21):

error: the switch expression does not cover all possible input values

Это та же идея, что @Override и @FunctionalInterface: ошибка всплывает там, где её сделали, а не у пользователя в продакшене.

2. record: объект-значение в одну строку

Твой AccountNumber — 40 строк: поле, конструктор с проверкой, геттер, equals, hashCode. Для объектов-значений (урок 8) в Java 16 появились записи (Oracle: Record Classes):

public record AccountNumber(String value) { }

Компилятор сам создаёт:

private final String value;
поле — final, после создания не меняется
AccountNumber(String value)
конструктор со всеми полями
value()
метод доступа. Без get: number.value(), не getValue()
equals, hashCode
по всем полям — ровно то, что ты писал руками в уроке 8
toString
AccountNumber[value=BANK-1]

Проверено: два new AccountNumber("BANK-1") равны по equals, не равны по ==, у них одинаковый hashCode, в HashSet — один элемент. Все твои проверки урока 8 пройдут без единой строки equals.

Проверка в компактном конструкторе

Инвариант из урока 3 — «номер всегда начинается с BANK» — остаётся. Для этого есть компактный конструктор: без скобок с параметрами и без присваивания полей, только проверка:

public record AccountNumber(String value) {
    public AccountNumber {
        if (value == null || !value.startsWith("BANK")) {
            throw new IllegalArgumentException("Некорректный номер: " + value);
        }
    }
}

Поле присвоится само после проверки.

Чего record не умеет

ПопыткаОшибка (JDK 21)
number.value = "X"cannot assign a value to final variable value
class X extends AccountNumbercannot inherit from final AccountNumber
number.getValue()cannot find symbol: method getValue()

Поэтому BankAccount записью делать нельзя и не нужно: у счёта меняется баланс, у него есть наследник SavingsAccount, и это сущность, а не значение (урок 8).

3. Optional: «может не найтись» — в типе

В Spring Data метод findById объявлен так:

Optional<T> findById(ID id);

Optional<T> — коробка, в которой либо лежит одно значение, либо пусто. Ты уже видел её: max() и findFirst() у стрима возвращали Optional[Ilya: 123123] или Optional.empty. Смысл: тот, кто вызывает метод, по сигнатуре видит, что результата может не быть, и обязан решить, что делать.

Создать

Optional.of(account)            // точно не null
Optional.empty()                // пусто
Optional.ofNullable(map.get(id))  // null → empty, иначе — значение

Достать

Проверено на мапе, где по номеру BANK-1 лежит "Ilya":

МетодНайденоНе найдено
orElse("никто")Ilyaникто
orElseThrow(() -> new IllegalStateException("Счёт не найден"))Ilyaбросает твоё исключение
map(String::toUpperCase).orElse("?")ILYA?
ifPresent(o -> …)выполнит лямбдуничего
isPresent() / isEmpty()true / falsefalse / true
get()IlyaNoSuchElementException: No value present

orElseThrow принимает Supplier из урока 11 — лямбду без параметров, которая создаёт исключение. Это ровно то, что нужно твоему банку: репозиторий честно говорит «может не быть», а банк решает «если нет — AccountNotFoundException».

Как не надо

if (opt.isPresent()) {           // это тот же if (x != null), только длиннее
    return opt.get();
}
return null;                     // и снова null!

Правила: не вызывай get() без проверки (лучше вообще orElseThrow()); не возвращай null из метода, который возвращает Optional; Optional — для возвращаемых значений, не для полей и параметров.

Частые вопросы

Когда record, а когда обычный класс?

record — когда объект определяется данными и не меняется: номер счёта, деньги, координаты, ответ API. Обычный класс — когда есть изменяемое состояние (баланс), наследование или идентичность (сущность). Вопрос «равны ли два таких объекта с одинаковыми полями?» — если да, это кандидат в record.

Почему у record метод value(), а не getValue()?

Так решили авторы языка: имя метода совпадает с именем компонента. Библиотеки (например, Jackson в Spring) это понимают. Привыкнуть надо только тебе — компилятор подскажет, если напишешь get.

Выбросить исключение или вернуть Optional?

Если «не нашлось» — нормальная ситуация (поиск по номеру, который ввёл пользователь) — Optional, пусть вызывающий решит. Если «не нашлось» означает ошибку в программе или нарушенный договор — исключение. Частый компромисс, как в Spring: репозиторий возвращает Optional, сервис превращает пустоту в исключение через orElseThrow.

Проверь себя

1. Почему константы enum можно сравнивать через ==?

Объекты констант создаются один раз, второго RUB нет — значит, равные по смыслу константы всегда один и тот же объект.

2. record AccountNumber(String value) { }. Как получить значение?

Метод доступа называется как компонент, без get. Поле private final.

3. В enum добавили константу CNY, а в switch-выражении по валюте её нет. Что будет?

the switch expression does not cover all possible input values — компилятор требует перебрать все константы.

4. Что вернёт Optional.empty().orElse("никто")?

orElse — «значение или вот это». Исключение бросил бы get().

5. Почему BankAccount не стоит делать записью?

Поля записи неизменяемы, а у счёта меняется баланс. Плюс у счёта есть наследник, а запись — final. И счёт — сущность, а не значение.
