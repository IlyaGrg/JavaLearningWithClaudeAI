Лямбды и Comparator: передать поведение как значение

После этого урока ты сможешь писать лямбды и ссылки на методы, сортировать счета по любому признаку без изменения класса и переписать свои циклы группировки в одну строку.

Зачем этот урок для backend. Лямбды в современном Java-коде везде: сортировка, фильтры, Stream API (урок 12), обработчики в Spring, настройка Spring Security — это цепочки лямбд. Без них код Spring-проекта просто не читается. А на собеседовании почти наверняка спросят «что такое функциональный интерфейс».

1. Проблема: поведение, которое хочется передать

Твой BankAccount реализует Comparable — сравнивает по балансу. Это его «естественный порядок» (урок 6). А если в одном месте нужен список по владельцу, в другом — по убыванию баланса? Менять compareTo нельзя: он один на класс.

Нужен способ передать в sort правило сравнения отдельно от класса. Для этого есть интерфейс Comparator<T> с одним методом compare(a, b). До Java 8 его реализовывали анонимным классом — классом без имени, объявленным прямо на месте:

accounts.sort(new Comparator<BankAccount>() {
    @Override
    public int compare(BankAccount a, BankAccount b) {
        return a.getOwner().compareTo(b.getOwner());
    }
});

Шесть строк, из которых полезная — одна. Остальное — церемония.

2. Лямбда

Лямбда — это та же реализация, но без церемонии (Oracle: Lambda Expressions):

accounts.sort((a, b) -> a.getOwner().compareTo(b.getOwner()));
(a, b)
параметры метода compare. Типы не пишем — компилятор знает, что это BankAccount, из List<BankAccount>
->
«превращается в»
a.getOwner()…
тело. Если это одно выражение — без {} и без return, его значение и есть результат

Варианты записи:

acc -> acc.getBalance() > 1000            // один параметр — скобки можно опустить
() -> new ArrayList<>()                   // без параметров
(a, b) -> {                                // несколько строк — фигурные скобки и return
    int byOwner = a.getOwner().compareTo(b.getOwner());
    return byOwner != 0 ? byOwner : Integer.compare(a.getBalance(), b.getBalance());
}

Где можно написать лямбду

Только там, где ожидается функциональный интерфейс — интерфейс ровно с одним абстрактным методом. Лямбда и есть реализация этого метода. Твой Notifier — функциональный интерфейс:

Notifier sms = (to, msg) -> System.out.println("SMS " + to + ": " + msg);
sms.send("Ilya", "Перевод 100");     // SMS Ilya: Перевод 100

List<String> sent = new ArrayList<>();
Notifier fake = (to, msg) -> sent.add(to + ":" + msg);   // фейк без отдельного класса

Если методов два — лямбду не написать (проверено на JDK 21):

error: incompatible types: Two is not a functional interface
    multiple non-overriding abstract methods found in interface Two

Аннотация @FunctionalInterface над интерфейсом просит компилятор проверить это правило — как @Override для методов.

Готовые функциональные интерфейсы

Чтобы не объявлять свой интерфейс на каждый случай, в пакете java.util.function есть стандартные. Четыре главных:

ИнтерфейсМетодСмыслПример
Predicate<T>boolean test(T)условиеacc -> acc.getBalance() > 1000
Function<T, R>R apply(T)превратить T в Racc -> acc.getOwner()
Consumer<T>void accept(T)сделать что-то с Tacc -> System.out.println(acc)
Supplier<T>T get()выдать новое T() -> new ArrayList<>()

Видишь generics из урока 9? Predicate<BankAccount> — условие про счёт, Function<BankAccount, String> — из счёта получить строку.

Переменные снаружи — только «фактически final»

int total = 0;
list.forEach(x -> total += x);
// error: local variables referenced from a lambda expression must be final or effectively final

Лямбда может читать локальные переменные снаружи, но только те, которые после присваивания не меняются. Менять их изнутри нельзя. При этом менять объект по ссылке можно: sent.add(...) в фейке выше работает, потому что сама переменная sent не меняется — меняется список, на который она указывает (урок 2, ссылки).

3. Ссылки на методы

Когда лямбда только вызывает один готовый метод, её можно сократить ещё (Oracle: Method References):

ЛямбдаСсылка на метод
acc -> acc.getOwner()BankAccount::getOwner
x -> System.out.println(x)System.out::println
(a, b) -> Integer.sum(a, b)Integer::sum
() -> new ArrayList<>()ArrayList::new

Читается как «метод getOwner класса BankAccount». Скобок нет — метод не вызывается сейчас, а передаётся, чтобы его вызвали потом.

4. Comparator: собрать сортировку из кусочков

Писать compare руками почти не приходится. У Comparator есть методы, которые строят его из ссылки на геттер:

accounts.sort(Comparator.comparing(BankAccount::getOwner));          // по владельцу, А→Я
accounts.sort(Comparator.comparingInt(BankAccount::getBalance));     // по балансу (int)

accounts.sort(Comparator.comparing(BankAccount::getOwner)
                        .thenComparingInt(BankAccount::getBalance)); // по владельцу, при равенстве — по балансу

accounts.sort(Comparator.comparingInt(BankAccount::getBalance)
                        .reversed());                                // по убыванию баланса

Проверено на счетах Valeria 500, Ilya 120, Ilya 900, Anna 500: «по владельцу, потом по балансу» даёт [Anna: 500, Ilya: 120, Ilya: 900, Valeria: 500].

comparingInt вместо comparing для int — чтобы не упаковывать числа в Integer (урок 7). Работает и comparing, но так точнее.

Ловушка: reversed() после лямбды

Comparator.comparing(b -> b.getOwner()).reversed()
// error: cannot find symbol
//   symbol:   method getOwner()
//   location: variable b of type Object

Компилятор выводит тип b из того, куда идёт результат. Но здесь результат сначала уходит в .reversed(), и компилятор не успевает понять, что b — счёт, считает его Object. Решение — ссылка на метод BankAccount::getOwner: в ней тип написан явно.

5. Map с лямбдами: было и стало

Твой balanceByOwner из урока 7 — шаблон «подсчёт»:

balanceAndOwner.put(owner, balanceAndOwner.getOrDefault(owner, 0) + user.getBalance());

У Map есть merge: «если ключа нет — положи значение, если есть — объедини старое с новым функцией»:

balanceAndOwner.merge(owner, user.getBalance(), Integer::sum);
// Ilya 100, Ilya 50, Anna 7  →  {Anna=7, Ilya=150}

А шаблон «достань → если null создай и положи → добавь» из accountsByOwner — это computeIfAbsent. Он возвращает список из мапы — существующий или только что созданный лямбдой:

userAccounts.computeIfAbsent(owner, k -> new ArrayList<>()).add(user);

Пять строк — в одну. Логика та же, которую ты уже понимаешь, — поэтому и учим это сейчас, а не в уроке 7.

Ещё два метода коллекций

accounts.removeIf(acc -> acc.getBalance() == 0);   // удалить по условию — без ConcurrentModificationException
accounts.forEach(System.out::println);             // для каждого

removeIf решает проблему урока 7: удалять из списка внутри for-each нельзя, а так — можно.

Частые вопросы

Лямбда — это объект?

Да: это объект, реализующий функциональный интерфейс. Его можно положить в переменную, передать в метод, вернуть из метода. Отсюда и выражение «передать поведение как значение».

Когда лямбда, а когда обычный класс?

Лямбда — когда реализация короткая (одна-три строки) и нужна в одном месте. Если логика большая, нужна в нескольких местах или у реализации есть своё состояние и другие методы — обычный класс. Твои ConsoleSmsNotifier и FakeNotifier остаются нормальным решением, лямбда — просто короче.

Comparable или Comparator?

Comparable — один «естественный» порядок, зашитый в класс (compareTo). Comparator — сколько угодно порядков снаружи, класс не меняется. Для сущностей вроде счёта естественного порядка часто нет вовсе, и тогда пишут только компараторы.

Проверь себя

1. Что такое функциональный интерфейс?

Правило — один абстрактный метод. Пакет java.util.function содержит готовые, но твой Notifier тоже функциональный. Аннотация только просит компилятор проверить.

2. Чему равна ссылка на метод BankAccount::getOwner?

Ссылка на метод — сокращённая лямбда. Метод не вызывается сейчас: его вызовут позже, для каждого счёта.

3. Как отсортирует Comparator.comparingInt(BankAccount::getBalance).reversed()?

comparingInt — по возрастанию баланса, reversed() переворачивает порядок.

4. int total = 0; list.forEach(x -> total += x); Что будет?

Лямбда не может менять локальные переменные снаружи: must be final or effectively final.

5. В мапе {Ilya=100}. Что станет после map.merge("Ilya", 50, Integer::sum)?

Ключ есть — merge объединяет старое и новое функцией Integer::sum: 100 + 50. Не было бы ключа — положил бы 50.
