Generics: один класс для разных типов

После этого урока ты сможешь прочитать любые угловые скобки — List<E>, Map<K, V>, Comparable<T>, — написать свой обобщённый класс и обобщённый метод, и понять, как устроен репозиторий в Spring Data.

Зачем этот урок для backend. В Spring Data ты будешь писать interface AccountRepository extends CrudRepository<Account, Long> — и получать готовые методы сохранения и поиска для любого класса. Это работает благодаря generics. В домашке ты напишешь упрощённую версию такого репозитория сам.

Разминка: вспомни урок 8

1. Integer x = 500, y = 500; — что даст x == y и почему?

false. Integer — объект, == сравнивает ссылки, а кеш гарантирован только для −128…127. Сравнивать нужно через equals.

2. В equals(Object o) была строка Money other = (Money) o;. Зачем она?

Это приведение типа. У переменной типа Object нельзя спросить amount — компилятор смотрит на тип переменной. Мы проверили, что объект действительно Money, и смотрим на него через переменную типа Money. Сегодня увидим, сколько таких приведений приходилось писать до появления generics.

3. Ты уже много раз писал <...>. Где?

ArrayList<Product>, Map<AccountNumber, BankAccount>, Comparable<BankAccount>, new HashMap<>(). Ты пользовался generics с урока 2, не зная, как они называются. Сегодня — что за этим стоит.

1. Жизнь без generics

Generics появились в Java 5 (2004 год). До этого List хранил просто «объекты» — Object. Этот старый стиль до сих пор компилируется, его называют сырым типом (raw type):

List raw = new ArrayList();         // без угловых скобок
raw.add("Чай");
raw.add(250);                       // компилятор не возражает: всё — Object

String s = (String) raw.get(1);     // нужно приведение, и оно...
// ClassCastException: class java.lang.Integer cannot be cast to class java.lang.String

Проверено на JDK 21. Проблемы видны сразу:

  • Каждое чтение — с приведением типа, как (Money) o в equals.
  • Ошибка обнаруживается при запуске, а не при компиляции. В список легко положить число, а упадёт программа где-то далеко, там, где его достают как строку. Это тот самый «дорогой» вид бага из урока 3: ошибка проявляется далеко от места, где её сделали.

Компилятор, кстати, при сборке этого кода предупреждает: Note: Main.java uses unchecked or unsafe operations. Это намёк: «тут сырые типы, я не могу проверить».

Теперь то же самое с generics:

List<String> names = new ArrayList<>();
names.add(250);
// error: incompatible types: int cannot be converted to String

Ошибка — при компиляции, на той самой строке, где её сделали. А при чтении приведение не нужно: String s = names.get(0); — компилятор знает, что там строки.

Generics переносят проверку типов из выполнения в компиляцию. Это главное, ради чего они существуют.

Python

names: list[str] = []
names.append(250)   # запустится!
# подсказку проверяет только
# внешний инструмент (mypy)

Java

List<String> names = new ArrayList<>();
names.add(250);     // не скомпилируется
// проверяет сам компилятор

2. Как читать угловые скобки

Открой документацию ArrayList, и увидишь class ArrayList<E>, а метод add записан как add(E e), get — как E get(int index). Что такое E?

E — параметр типа (type parameter). Это «переменная, в которую положат тип». Когда ты пишешь ArrayList<String>, ты передаёшь аргумент типа String, и везде вместо E подставляется String: add(String e), String get(int index).

Аналогия с методом из урока 1 почти буквальная:

МетодGeneric-класс
Объявлениеint square(int x)class Box<T>
Параметрx — какое-то числоT — какой-то тип
Использованиеsquare(5)Box<String>
Аргумент5String

Имена параметров типа по соглашению — одна заглавная буква:

  • T — Type, «какой-то тип»;
  • E — Element, элемент коллекции (List<E>, Set<E>);
  • K, V — Key и Value (Map<K, V>);
  • ID — иногда пишут и так, для идентификатора (Spring Data).

Теперь ты можешь прочитать Comparable<T> из урока 6: «сравнимый с чем-то типа T». У него метод int compareTo(T o). Ты написал implements Comparable<BankAccount> — значит, T = BankAccount, и твой метод — compareTo(BankAccount other).

BankAccount: вместо V подставился второй аргумент типа. Поэтому в уроке 7 ты писал BankAccount acc = accounts.get(number); без всякого приведения.

3. Свой generic-класс

Задача: вернуть из метода два значения разных типов — например, название товара и его цену. Можно написать класс NameAndPrice, потом OwnerAndBalance, потом ещё десяток почти одинаковых. А можно один раз:

Pair.java

public class Pair<A, B> {
    private A first;
    private B second;

    public Pair(A first, B second) {
        this.first = first;
        this.second = second;
    }

    public A getFirst() {
        return first;
    }

    public B getSecond() {
        return second;
    }

    @Override
    public String toString() {
        return "(" + first + ", " + second + ")";
    }
}
public class Pair<A, B>
Объявление двух параметров типа: A и B. Внутри класса они используются как обычные типы. Какими они будут — решит тот, кто создаёт объект.
private A first;
Поле «какого-то типа A». В Pair<String, Integer> это будет String.
public Pair(A first, B second)
Конструктор. Обрати внимание: у имени конструктора угловых скобок нет — только у имени класса.
public A getFirst()
Возвращает «тот самый A». Для Pair<String, Integer> — String, приведение не нужно.

Использование (проверено на JDK 21):

Pair<String, Integer> p = new Pair<>("Чай", 250);
String name = p.getFirst();          // без приведения
int price = p.getSecond();           // Integer → int автоматически (урок 7)
System.out.println(p);               // (Чай, 250)

Pair<String, List<String>> q = new Pair<>("Илья", List.of("карта", "вклад"));
q.getSecond().size();                // 2 — внутрь можно положить даже список

String s = p.getSecond();
// error: incompatible types: Integer cannot be converted to String

Один класс работает для любых типов, и при этом компилятор следит за каждым. new Pair<>(...) — тот же «ромб», что у new ArrayList<>(): Java выводит аргументы типа из левой части.

Ограничения

Только ссылочные типы. Pair<String, int> не скомпилируется — unexpected type, required: reference, found: int. Та же причина, что с List<int> в уроке 7: используй Integer.

Нельзя new T(). Внутри класса нельзя создать объект параметра типа: error: unexpected type, required: class, found: type parameter T. Во время выполнения Java уже не знает, какой тип был подставлен (это называется стирание типов, type erasure — generics существуют только для компилятора). Поэтому объекты типа T generic-класс получает снаружи, как Pair в конструкторе.

Источник: Oracle — Restrictions on Generics.

Проверь себя: какие типы у getFirst() и getSecond() для Pair<AccountNumber, BankAccount>?

AccountNumber и BankAccount. Подставляется по порядку: первый аргумент — в A, второй — в B.

4. Generic-метод

Параметр типа можно объявить не у всего класса, а у одного метода. Помнишь, сколько раз мы писали «если список пуст — исключение, иначе первый элемент»? Сделаем это один раз для списков чего угодно:

public static <T> T firstOrThrow(List<T> list) {
    if (list.isEmpty()) {
        throw new IllegalArgumentException("Список пуст");
    }
    return list.get(0);
}
public static <T>
Объявление параметра типа для этого метода. Стоит перед типом результата. Без него компилятор не поймёт, что такое T в остальной сигнатуре.
T firstOrThrow(List<T> list)
«Принимает список чего-то типа T и возвращает T». Связь между входом и выходом — главное: для списка строк вернётся строка, для списка счетов — счёт.
String s = Utils.firstOrThrow(List.of("a", "b"));          // "a"
BankAccount acc = Utils.firstOrThrow(accounts);            // без приведения
Utils.firstOrThrow(new ArrayList<Integer>());              // Список пуст

При вызове T писать не нужно: компилятор сам выводит его из аргумента (List<String> → T = String). Это называется выведение типа. Явно тоже можно — Utils.<Integer>firstOrThrow(...), — но так пишут редко.

Источник: Oracle — Generic Methods.

5. Ограничение типа: <T extends Comparable<T>>

Напишем «найти максимум в списке» для любого типа. Первая попытка:

public static <T> T max(List<T> list) {
    T best = list.get(0);
    for (T item : list) {
        if (item.compareTo(best) > 0) {   // ← ошибка
            best = item;
        }
    }
    return best;
}
// error: cannot find symbol
//   symbol:   method compareTo(T)
//   location: variable item of type T

Почему: T — любой тип. Это может быть и Pair, у которого нет compareTo. По правилу из урока 5 компилятор разрешает только то, что точно есть у типа переменной, а про произвольный T он знает лишь, что это Object.

Нужно сузить: «T — не любой тип, а только сравнимый». Это пишется так:

public static <T extends Comparable<T>> T max(List<T> list) {
    T best = firstOrThrow(list);
    for (T item : list) {
        if (item.compareTo(best) > 0) {
            best = item;
        }
    }
    return best;
}
<T extends Comparable<T>>
«T — любой тип, который реализует Comparable<T>», то есть умеет сравниваться с такими же, как он. В угловых скобках extends означает и «наследует класс», и «реализует интерфейс». Теперь компилятор знает, что у item есть compareTo.
T best = firstOrThrow(list);
Один generic-метод вызывает другой. Пустой список — понятное исключение.

Проверено:

Utils.max(List.of(3, 17, 5));                     // 17 — Integer сравним
Utils.max(List.of("груша", "яблоко", "арбуз"));   // яблоко — String сравним
Utils.max(List.of(new Pair<>("a", 1)));           // ошибка компиляции:
// method max in class ... cannot be applied to given types

Последний вызов отклонён ещё при компиляции: Pair не реализует Comparable. А твой BankAccount — реализует, так что max найдёт счёт с наибольшим балансом. Это проверишь в домашке.

Источник: Oracle — Bounded Type Parameters.

Проверь себя: в уроке 6 сообщение об ошибке Collections.sort содержало T#1 extends Comparable<? super T#1>. Что это значит теперь?

У Collections.sort тоже ограничение: элементы списка должны быть сравнимыми. Поэтому сортировка класса без Comparable не компилировалась. Знак ? — wildcard, его разберём в частых вопросах; суть та же.

6. Как это выглядит в Spring

В Spring Data есть интерфейс CrudRepository<T, ID> (документация): T — тип сущности, ID — тип её идентификатора. В нём объявлены методы вроде save(T entity), findById(ID id), findAll(), count(), deleteById(ID id). Ты пишешь:

interface AccountRepository extends CrudRepository<Account, Long> { }

и получаешь все эти методы для счетов, где T = Account, ID = Long. Одна и та же библиотека работает со счетами, клиентами, заказами — с любыми твоими классами. Без generics её пришлось бы писать заново для каждого класса или возвращать Object и приводить типы на каждом шагу. В домашке ты сделаешь упрощённую версию: Repository<T, ID>, хранящий данные в Map.

7. Частые вопросы

Что такое ? в List<? extends Number>?

Это wildcard — «какой-то тип, не важно какой». List<? extends Number> — «список чего-то, что является Number»: подойдёт и List<Integer>, и List<Double>. Встречается в сигнатурах библиотек. Важная деталь: List<Integer> — это не List<Number>, хотя Integer — это Number. Иначе можно было бы положить Double в список целых. Писать wildcard самому пока не нужно, достаточно узнавать при чтении.

Oracle — Wildcards.

Почему нельзя new T(), а new ArrayList<T>() внутри generic-класса — можно?

new ArrayList<T>() создаёт объект конкретного класса ArrayList — его Java знает. А new T() требует знать сам T во время выполнения, а он к тому времени стёрт. В домашке ты будешь создавать new HashMap<>() внутри generic-класса — это нормально.

Что значит предупреждение «uses unchecked or unsafe operations»?

Где-то используется сырой тип (List без скобок) или непроверяемое приведение. Компилятор не может гарантировать типы. В своём коде сырых типов не пиши никогда. Если видишь это предупреждение — ищи, где забыл <...>.

Можно ли сделать generic-интерфейс?

Да, ты им уже пользовался: Comparable<T>, List<E>, Map<K, V> — интерфейсы. Объявляется так же: public interface Repository<T, ID> { ... }. А реализующий класс либо подставляет конкретные типы (implements Comparable<BankAccount>), либо сам остаётся generic (class InMemoryRepository<T, ID> implements Repository<T, ID>).

8. Проверь себя

Без подглядывания. Ошибся — вернись к разделу.

1. List<String> names, вызов names.add(250). Когда обнаружится ошибка?

Generics переносят проверку типов в компиляцию: incompatible types: int cannot be converted to String. Без них (сырой тип) ошибка всплыла бы при выполнении.

2. Что такое A в объявлении class Pair<A, B>?

A — как параметр метода, только для типа. В Pair<String, Integer> вместо него подставится String.

3. Зачем в max написано <T extends Comparable<T>>, а не просто <T>?

Про произвольный T компилятор знает только, что это Object. Ограничение обещает, что у T есть compareTo.

4. Что будет с объявлением Pair<String, int> p;?

Аргументы типа — только ссылочные типы: unexpected type, required: reference, found: int. Автоупаковка работает для значений, а не для аргументов типа.

5. List raw = new ArrayList(); raw.add(250); String s = (String) raw.get(0); Что будет?

Сырой тип принимает любой Object, компилятор только предупреждает. Приведение Integer к String падает при выполнении.

Шаг 1. Интерфейс Repository<T, ID>

Generic-интерфейс в духе Spring Data. T — что храним, ID — по какому ключу. Методы:

  • void save(ID id, T item) — сохранить (если такой id уже есть — заменить);
  • T findById(ID id) — найти; если нет — исключение (своё или стандартное, реши сам);
  • boolean existsById(ID id);
  • List<T> findAll() — все элементы, новым списком (урок 7: почему не само поле?);
  • int count();
  • void deleteById(ID id).

Шаг 2. InMemoryRepository<T, ID> implements Repository<T, ID>

Реализация, которая хранит всё в private Map<ID, T>. Класс сам остаётся generic — конкретные типы подставит тот, кто его создаёт. Аргументы null не принимай.
