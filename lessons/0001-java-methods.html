Методы: как разрезать программу на понятные куски

После этого урока ты сможешь сам написать метод с параметрами и возвращаемым значением и предсказать, изменит ли он твои данные.

Зачем это backend-разработчику

Любое backend-приложение — это цепочка вызовов методов. Пользователь нажимает «Оформить заказ», запрос приходит на сервер, и дальше один метод вызывает другой: принять запрос → проверить данные → посчитать сумму → сохранить в базу. Когда через год ты откроешь проект на Spring Boot, ты увидишь сотни методов. Каждый устроен по правилам из этого урока.

А ещё методы — это мост к ООП: класс в следующем уроке окажется «данными + методами, которые с ними работают».

1. Ты это уже знаешь — по Python

Метод в Java — то же, что функция в Python. Разница в одном: Java требует заранее указать типы — что метод принимает и что возвращает.

Python

def add(a, b):
    return a + b

print(add(2, 3))

Java

static int add(int a, int b) {
    return a + b;
}

System.out.println(add(2, 3));

Зачем такие строгости? Компилятор проверяет типы до запуска. В Python add("2", 3) упадёт только во время работы программы. В Java такой код просто не скомпилируется: ошибку ты увидишь сразу, ещё в IntelliJ. Для банковского backend это огромный плюс — ошибка с деньгами не доедет до продакшена.

2. Полная программа, разбор каждой строки

Задача: посчитать сумму корзины из массива цен. Создай в IntelliJ файл Main.java, перепиши код руками (не копируй — так он лучше запомнится) и запусти.

public class Main {
Весь код в Java живёт внутри класса. Имя класса совпадает с именем файла: Main → Main.java. Что такое класс по-настоящему, разберём в уроке 2.
public static void main(String[] args) {
Точка входа — отсюда JVM начинает выполнение. Это тоже метод: void — ничего не возвращает, String[] args — аргументы командной строки.
int[] prices = {120, 450, 90};
Массив цен корзины. Это ты уже знаешь.
int total = sum(prices);
Вызов метода. Передаём prices, метод возвращает int, результат кладём в total. Тип переменной должен совпадать с типом, который возвращает метод.
System.out.println("Итого: " + total);
Печатает Итого: 660.
}
Конец main.
Пустая строка: методы пишутся рядом друг с другом внутри класса, но не вложенно (в Java нельзя объявить метод внутри метода).
static int sum(int[] numbers) {
Объявление метода — разбор по словам ниже, в разделе 3.
int result = 0;
Локальная переменная. Живёт только внутри sum, снаружи её не видно.
for (int n : numbers) {
for-each по массиву — тоже знакомо.
result += n;
Копим сумму.
}
return result;
return делает две вещи: завершает метод и отдаёт значение туда, откуда его вызвали, — в строку int total = sum(prices);.
}
Конец sum.
}
Конец класса.

3. Анатомия объявления метода

Строку static int sum(int[] numbers) разберём по словам:

static
Модификатор. Пока правило простое: если вызываешь метод прямо из main, пиши static. Почему — станет ясно в уроке про классы и объекты. Ещё бывают модификаторы доступа (public, private) — тоже в уроке 2.
int
Тип возвращаемого значения. Любой тип (int, double, boolean, String, int[], ArrayList<String>…) или void, если метод ничего не возвращает.
sum
Имя. По соглашению — глагол в camelCase: calculateTotal, isEmpty, findMax. Не Sum, не calculate_total (это стиль Python).
(int[] numbers)
Параметры: для каждого указывается тип и имя, через запятую. Может быть пусто: ().
{ ... }
Тело метода в фигурных скобках.

Источник: Oracle, The Java Tutorials — Defining Methods. Там же — соглашение об именах «глагол в нижнем регистре».

Компилятор проверяет, что return есть на каждом пути

Если метод объявил, что вернёт int, он обязан вернуть int при любых входных данных. Этот код не скомпилируется:

static int sign(int n) {
    if (n > 0) return 1;
    if (n < 0) return -1;
}   // ошибка: missing return statement — а если n == 0?

Python молча вернул бы None, а Java заставляет тебя подумать о каждом случае.

void: метод-действие

static void printReceipt(int total) {
    System.out.println("Чек: " + total + " руб.");
}

Его нельзя присвоить переменной: int x = printReceipt(5); — ошибка компиляции. Внутри void-метода можно написать пустой return;, чтобы выйти пораньше.

4. Самое важное: что метод может сделать с твоими данными

В Java аргументы всегда передаются по значению: метод получает копию того, что лежит в переменной. Вся хитрость в том, что именно лежит в переменной.

Примитивы (int, double, boolean, char…): копируется само число

static void addBonus(int balance) {
    balance = balance + 100;      // меняем КОПИЮ
}

int myBalance = 500;
addBonus(myBalance);
System.out.println(myBalance);   // ?
Сначала предскажи, потом открой

500. Метод получил копию числа 500 и увеличил копию. Переменная myBalance в main не тронута.

Массивы, списки, объекты: копируется ссылка

В переменной типа int[] или ArrayList лежит не сам массив, а ссылка на него («адрес»). Метод получает копию адреса, но адрес ведёт к тому же самому массиву.

static void applyDiscount(int[] prices) {
    for (int i = 0; i < prices.length; i++) {
        prices[i] = prices[i] / 2;   // меняем СОДЕРЖИМОЕ общего массива
    }
}

int[] cart = {100, 200};
applyDiscount(cart);
System.out.println(cart[0]);        // ?
Сначала предскажи, потом открой

50. И cart, и prices указывают на один массив, поэтому изменения видны снаружи.

Но если внутри метода присвоить параметру новый массив, то перезаписывается только копия адреса:

static void reset(int[] prices) {
    prices = new int[]{0, 0};   // копия ссылки теперь ведёт на НОВЫЙ массив
}

int[] cart = {100, 200};
reset(cart);
System.out.println(cart[0]);   // 100 — старый массив никто не трогал

Как в Python. Здесь Java ведёт себя почти так же, как Python со списками: lst.append(1) внутри функции видно снаружи, а lst = [] — нет. Примитивы Java ведут себя как числа в Python: изменить их «на месте» нельзя.

Источник: Oracle — Passing Information to a Method: «Reference data type parameters, such as objects, are also passed into methods by value».

Почему это важно на работе: один из классических багов в backend — метод «просто посчитать» случайно меняет переданный ему список, и данные портятся в другом месте программы. Вопрос «передаёт ли Java по ссылке?» любят на собеседованиях. Правильный ответ: нет, всегда по значению; для объектов по значению передаётся ссылка.

5. Перегрузка: одно имя — разные параметры

В одном классе может быть несколько методов с одним именем, если у них разные списки параметров (количество или типы). Компилятор выбирает нужный по аргументам.

static int sum(int a, int b)       { return a + b; }
static int sum(int[] numbers)      { /* как выше */ }
static double sum(double a, double b) { return a + b; }

sum(2, 3);          // вызовет первый
sum(new int[]{1,2}); // второй
sum(1.5, 2.0);      // третий

Ты уже пользовался перегрузкой, не зная об этом: System.out.println — это много методов с одним именем: для int, для String, для double…

Ловушка: тип возвращаемого значения в выборе не участвует. Методы int f(int x) и long f(int x) в одном классе — ошибка компиляции: по вызову f(5) их не различить.

Источник: Oracle — Defining Methods, раздел Overloading Methods.

6. Проверь себя

Отвечай по памяти, не прокручивая вверх: именно усилие при вспоминании закрепляет материал.

1. Что напечатает программа? 
static void change(int x) { x = 99; }
// в main:
int a = 5;
change(a);
System.out.println(a);

Метод получил копию числа. Изменение копии не трогает a.

2. А теперь? 
static void change(int[] arr) { arr[0] = 99; }
// в main:
int[] a = {5, 6};
change(a);
System.out.println(a[0]);

Скопировалась ссылка, а массив один и тот же. Метод изменил его содержимое.

3. А так? 
static void change(int[] arr) { arr = new int[]{99, 99}; }
// в main:
int[] a = {5, 6};
change(a);
System.out.println(a[0]);

Перезаписана только копия ссылки внутри метода. Переменная a по-прежнему указывает на старый массив {5, 6}.

4. Какая пара методов НЕ может быть в одном классе?

Параметры одинаковые, отличается только тип результата, а он в перегрузке не участвует. Вызов f(5) неоднозначен.

5. Почему этот метод не компилируется? 
static int sign(int n) {
    if (n > 0) return 1;
    if (n < 0) return -1;
}

При n == 0 метод дойдёт до конца без return. Компилятор требует вернуть int на любом пути.

Шаг 1. Файл src/lesson0001/Shop.java

Первой строкой файла пиши package lesson0001;. Пакет — это «папка» для классов: так у каждого урока может быть свой Main, и они не конфликтуют. Если создавать класс в IntelliJ правым кликом по папке lesson0001 → New → Java Class, строка появится сама. Подробно пакеты разберём позже.

Класс Shop с методом main и следующими static-методами. Каждый вызови из main хотя бы на двух разных входных данных и выведи результат.

  1. findMax(int[] prices) — возвращает самую большую цену. Тип возвращаемого значения выбери сам.
  2. average(int[] prices) — возвращает среднюю цену с дробной частью (для {1, 2} должно быть 1.5, а не 1). Подсказка: что получится в Java при 3 / 2?
  3. average(ArrayList<Integer> prices) — то же самое, но для списка. Да, с тем же именем: это перегрузка.
  4. isValidPromoCode(String code) — промокод валиден, если его длина ровно 8 символов и он начинается с "KZN". Возвращает boolean.
  5. applyDiscount(int[] prices, int percent) — уменьшает каждую цену в массиве на percent процентов и ничего не возвращает. В main выведи массив до и после вызова.
