Коллекции: List, Map и Set

После этого урока ты сможешь выбрать подходящую коллекцию под задачу, найти объект по ключу через Map, собрать уникальные значения через Set и обойти три типичные ловушки, на которых спотыкаются новички.

Хорошая новость. В Python ты уже пользовался всеми тремя: list, dict и set. Идеи те же самые. Новое — синтаксис, типы в угловых скобках и пара ловушек, которых в Python нет. Сегодня будем часто сравнивать.

Разминка: вспомни урок 6

1. List — это класс или интерфейс? А ArrayList?

List — интерфейс, договор «упорядоченная коллекция с доступом по номеру». ArrayList — класс, который его реализует. Это было в частых вопросах урока 6, и сегодня мы наконец начнём так писать.

2. Что делает Collections.sort(list) с твоими объектами и что для этого нужно?

Сортирует список, вызывая у элементов compareTo. Для этого класс элементов должен реализовать Comparable. Чужой код работает с твоим классом через интерфейс.

3. Твой FakeNotifier.getLastMessage() на пустом списке бросает исключение. Почему не вернуть просто messages.get(messages.size() - 1)?

На пустом списке это get(-1) — такого индекса нет, вылетит IndexOutOfBoundsException с невнятным для пользователя текстом. Своя проверка даёт понятное сообщение. Граничный случай «коллекция пуста» сегодня встретится снова.

1. Три вопроса — три коллекции

Массив (int[]) из первого урока имеет фиксированную длину. ArrayList из второго растёт сам. Но у реальных задач бывают разные главные вопросы:

Главный вопрос задачиКоллекция JavaВ PythonПример из банка
«Что лежит по порядку? Что под номером 3?»Listlistистория операций по счёту
«Что лежит под этим ключом?»Mapdictномер счёта → счёт
«Есть такой или нет? Без повторов»Setsetуникальные владельцы счетов

Все три — интерфейсы, а у каждого есть основная реализация: ArrayList, HashMap, HashSet. По уроку 6 ты уже знаешь, как принято писать: тип переменной — интерфейс, а после new — конкретный класс.

List<String> cart = new ArrayList<>();
Map<String, Integer> prices = new HashMap<>();
Set<String> customers = new HashSet<>();

Всё это лежит в пакете java.util, поэтому в начале файла нужен import java.util.List; и так далее (или сразу import java.util.*;).

Источник: Oracle — Collection Interfaces.

2. List: по порядку и по номеру

ArrayList ты знаешь. Новое — только тип переменной List, а методы те же. Я запустил этот код на JDK 21:

List<String> cart = new ArrayList<>();
cart.add("Чай");
cart.add("Кофе");
cart.add("Чай");                      // повторы разрешены

System.out.println(cart);             // [Чай, Кофе, Чай]
System.out.println(cart.size());      // 3
System.out.println(cart.get(1));      // Кофе — нумерация с 0
System.out.println(cart.contains("Кофе"));  // true
System.out.println(cart.indexOf("Чай"));    // 0 — первое вхождение

cart.remove("Чай");                   // удаляет ПЕРВОЕ вхождение
System.out.println(cart);             // [Кофе, Чай]
List<String>
«Список строк». В угловых скобках — тип элементов. Положить туда число компилятор не даст.
new ArrayList<>()
Пустые скобки <> («ромб») — Java сама подставит String из левой части.
cart.get(1)
Элемент по номеру. Номера с 0, как в Python. Только отрицательных индексов, как cart[-1], нет.
cart.get(10)
При трёх элементах — IndexOutOfBoundsException: Index 10 out of bounds for length 3. Python бросил бы IndexError, суть та же.

Когда List: важен порядок (что добавили раньше, что позже), нужны повторы, нужен доступ по номеру. Корзина, история операций, результаты поиска.

Когда не List: если ты постоянно ищешь элемент по какому-то признаку циклом — «найди счёт с номером X». contains и indexOf в списке перебирают все элементы по очереди. На 10 элементах незаметно, на миллионе счетов — очень медленно. Для поиска по ключу есть Map.

Проверь себя: что останется после cart.remove("Чай"), если в списке [Чай, Чай, Кофе]?

[Чай, Кофе]. remove(объект) удаляет только первое вхождение.

3. Числа в коллекциях: Integer вместо int

Попробуй написать List<int>. JDK 21:

error: unexpected type
  required: reference
  found:    int

Коллекции хранят только объекты (ссылочные типы), а int, double, boolean — примитивы. Для каждого примитива в Java есть класс-обёртка: Integer для int, Double для double, Boolean для boolean. Поэтому пишут List<Integer> и Map<String, Integer>.

Переводить туда-обратно руками не нужно: Java делает это сама (это называется автоупаковка, autoboxing). prices.put("Чай", 250) — число 250 автоматически станет объектом Integer, а int p = prices.get("Чай") — обратно.

Две ловушки обёрток

1. Integer может быть null, а int — нет. Если ключа в Map нет, get возвращает null (раздел 4). А при попытке положить его в int:

int x = prices.get("Мёд");   // ключа "Мёд" нет
// NullPointerException: Cannot invoke "java.lang.Integer.intValue()"
//   because the return value of "java.util.Map.get(Object)" is null

Сообщение проверено на JDK 21 и очень подробное: Java пыталась достать int из Integer (intValue()), а там был null, который вернул Map.get. Учись читать такие сообщения — в них всё сказано.

2. remove у List<Integer>. У списка два метода remove: по номеру remove(int index) и по объекту remove(Object o). Для списка чисел это коварно:

List<Integer> nums = new ArrayList<>(List.of(10, 20, 30));
nums.remove(1);                     // удалит элемент ПОД НОМЕРОМ 1
System.out.println(nums);           // [10, 30]
nums.remove(Integer.valueOf(10));   // удалит ЧИСЛО 10
System.out.println(nums);           // [30]

Это перегрузка из урока 1: Java выбирает метод по типу аргумента. 1 — это int, значит, вызывается версия с индексом.

4. Map: найти по ключу

Зачем: хранить пары «ключ → значение» и мгновенно находить значение по ключу. Номер счёта → счёт, название товара → цена, логин → пользователь.

Аналогия: гардероб. Ты сдаёшь пальто и получаешь номерок. Гардеробщик не перебирает все пальто подряд: по номерку он сразу идёт к нужному крючку. Номерок — ключ, пальто — значение. Два пальто на один номерок не повесить.

Map<String, Integer> prices = new HashMap<>();
prices.put("Чай", 250);
prices.put("Кофе", 800);
prices.put("Печенье", 120);

prices.get("Кофе");                  // 800
prices.get("Мёд");                   // null — такого ключа нет
prices.getOrDefault("Мёд", 0);       // 0 — значение по умолчанию
prices.containsKey("Чай");           // true

Integer old = prices.put("Чай", 300);  // ключ уже есть — значение ЗАМЕНЯЕТСЯ
// old = 250, prices.get("Чай") = 300, prices.size() = 3
Map<String, Integer>
Два типа: ключ — String, значение — Integer. Как dict[str, int] в аннотациях Python.
prices.put("Чай", 250)
Положить пару. В Python — prices["Чай"] = 250. Квадратных скобок у Map в Java нет.
prices.get("Мёд")
Ключа нет → null. В Python prices["Мёд"] бросил бы KeyError, а Java молча возвращает null. Это главное отличие от Python, и источник многих NullPointerException.
getOrDefault("Мёд", 0)
Как prices.get("Мёд", 0) в Python: если ключа нет, вернёт второй аргумент.
prices.put("Чай", 300)
Старое значение заменяется, а put возвращает его (или null, если ключа не было). Ключи в Map уникальны, значения — могут повторяться.

Шаблон «сохрани → проверь на null → используй» — снова

Ты освоил его в уроке 2 с findMostExpensive. С Map он нужен постоянно:

BankAccount acc = accounts.get(number);    // сохрани
if (acc == null) {                         // проверь
    throw new IllegalArgumentException("Счёт не найден: " + number);
}
acc.withdraw(500);                         // используй

Без проверки accounts.get("40817").getBalance() упадёт с NullPointerException: Cannot invoke "...getBalance()" because the return value of "java.util.Map.get(Object)" is null (проверено). Сообщение честно говорит, кто вернул null.

Обход Map

for (Map.Entry<String, Integer> e : prices.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}
for (String name : prices.keySet()) { ... }      // только ключи
for (int price : prices.values()) { ... }        // только значения
prices.entrySet()
Набор всех пар. Как prices.items() в Python.
Map.Entry<String, Integer> e
Одна пара. getKey() и getValue() — её ключ и значение. Тип длинный, но IntelliJ подставит его сам.
keySet() / values()
Как keys() и values() в Python.

Порядок. Я положил «Чай», «Кофе», «Печенье», а обход напечатал «Чай, Печенье, Кофе». HashMap не гарантирует никакого порядка — он раскладывает ключи так, чтобы быстро их находить, а не так, как ты их добавлял. В Python 3.7+ dict помнит порядок вставки, а HashMap — нет. Если порядок нужен:

  • LinkedHashMap — в порядке добавления (как dict в Python);
  • TreeMap — отсортированно по ключу.

Оба реализуют тот же интерфейс Map, поэтому меняется только то, что после new. Это и есть польза от переменной типа интерфейса из урока 6.

Частый приём: подсчёт

Сколько раз заказывали каждый товар?

String[] orders = {"Чай", "Кофе", "Чай", "Чай", "Печенье", "Кофе"};
Map<String, Integer> counts = new HashMap<>();
for (String o : orders) {
    counts.put(o, counts.getOrDefault(o, 0) + 1);
}
System.out.println(counts);    // {Чай=3, Печенье=1, Кофе=2}

Трассировка первых трёх шагов:

  1. o = "Чай": ключа нет → getOrDefault даёт 0 → put("Чай", 1).
  2. o = "Кофе": ключа нет → 0 → put("Кофе", 1).
  3. o = "Чай": ключ есть, значение 1 → put("Чай", 2) заменяет старое значение.

Этот приём встречается в задачах на собеседованиях так часто, что его стоит знать наизусть.

Источник: Oracle — The Map Interface.

Проверь себя: Map<String, BankAccount> accounts. Чем опасна строка accounts.get(number).withdraw(100)?

Если такого номера нет, get вернёт null, и вызов withdraw у null даст NullPointerException. Нужно сохранить результат, проверить на null и только потом использовать.

5. Set: только уникальные

Зачем: собрать значения без повторов и быстро проверять «есть ли такой». Уникальные владельцы, уже обработанные номера платежей, теги.

Set<String> customers = new HashSet<>();
customers.add("Илья");        // true  — добавлен
customers.add("Валерия");     // true
customers.add("Илья");        // false — уже есть, ничего не изменилось
customers.size();             // 2
customers.contains("Илья");   // true — и это быстро, без перебора

Обрати внимание: add возвращает boolean — «добавился ли элемент». Это удобно: if (!processed.add(paymentId)) { ... платёж уже был ... } — проверка и добавление в одной строке. Порядка у HashSet, как и у HashMap, нет. Есть LinkedHashSet и TreeSet.

Откуда Set знает, что «Илья» уже есть?

Строки он сравнивает по содержимому, а не по ссылке. Я проверил: два разных объекта new String("Илья") в HashSet дают размер 1. А теперь твой счёт:

Set<BankAccount> set = new HashSet<>();
set.add(new BankAccount("Илья", 100));
set.add(new BankAccount("Илья", 100));
System.out.println(set.size());   // ?

Подумай, что напечатается. Ответ — в домашке (шаг 5), а объяснение, почему, — тема урока 8 про equals и hashCode. Это тот же вопрос, что «== против содержимого» из урока 3, только теперь от него зависит работа Set и Map.

Источник: Oracle — The Set Interface.

6. Две ловушки при работе со списком

Удаление внутри for-each

List<String> cart = new ArrayList<>(List.of("Чай", "Кофе", "Печенье"));
for (String item : cart) {
    if (item.equals("Чай")) {
        cart.remove(item);
    }
}
// Exception in thread "main" java.util.ConcurrentModificationException

Нельзя менять список, пока по нему идёт for-each: цикл «запомнил», каким был список, и при следующем шаге обнаружил, что его изменили. Самое неприятное: я проверил тот же код с удалением «Кофе» (предпоследний элемент) — исключения нет, всё «работает». Ошибка, которая проявляется не всегда, хуже ошибки, которая есть всегда. Поэтому просто не делай так никогда.

Как правильно удалить по условию:

cart.removeIf(item -> item.equals("Чай"));

Запись item -> ... — лямбда, её разберём в уроке 11. Пока читай её как «удали каждый item, для которого верно условие справа от стрелки».

Неизменяемые списки List.of

List.of("Чай", "Кофе") — быстрый способ создать список из готовых значений. Но он неизменяемый: add или remove бросят UnsupportedOperationException (проверено). Если нужен изменяемый — оберни: new ArrayList<>(List.of(...)), как в примерах выше. То же с Set.of и Map.of.

7. Частые вопросы

Почему HashMap находит по ключу быстро, а List — медленно?

HashMap по ключу вычисляет число — хеш-код — и по нему сразу понимает, в какую «ячейку» смотреть, как гардеробщик по номерку. Список же сравнивает искомое с каждым элементом по очереди. Как именно считается хеш-код и почему для своих классов это надо настроить — урок 8.

Есть ещё LinkedList. Когда его брать?

Почти никогда. По умолчанию — ArrayList: он быстрее в большинстве реальных задач. Если однажды понадобится LinkedList, ты поймёшь это по замерам, а не заранее.

Map — это тоже Collection?

Нет, и это частый вопрос на собеседовании. List и Set наследуют общий интерфейс Collection («набор элементов»), а Map — отдельный интерфейс, потому что хранит не элементы, а пары. Поэтому у Map нет метода add, а есть put.

Можно ли хранить в Map список?

Да, значение может быть любым объектом, в том числе коллекцией: Map<String, List<BankAccount>> — «владелец → все его счета». Понадобится в домашке.

Можно ли положить в HashMap ключ null?

Технически можно (один), но не стоит: это почти всегда признак ошибки. Неизменяемые Map.of и List.of null вообще не принимают.

8. Проверь себя

Без подглядывания. Ошибся — вернись к разделу.

1. Банку нужно быстро находить счёт по его номеру. Что выбрать?

Главный вопрос задачи — «что лежит под этим ключом». Map находит значение по ключу без перебора, а список и массив пришлось бы проходить целиком.

2. В prices нет ключа «Мёд». Что вернёт prices.get("Мёд")?

В отличие от Python, Java не бросает исключение, а возвращает null. Отсюда шаблон «сохрани → проверь на null → используй» или getOrDefault.

3. customers.add("Илья") вызвали второй раз. Что вернёт метод?

Set хранит только уникальные элементы. add возвращает, изменился ли набор: повтор не добавляется, результат false.

4. List<Integer> nums содержит [10, 20, 30]. Что будет после nums.remove(1)?

1 — это int, поэтому вызывается remove(int index): удаляется элемент под номером 1. Чтобы удалить число, нужно remove(Integer.valueOf(1)).

5. Зачем писать List<String> cart = new ArrayList<>(), а не ArrayList<String> cart?

Идея урока 6: тип переменной — интерфейс. Реализацию можно поменять, исправив только то, что после new, остальной код не изменится.

Шаг 1. Класс Bank

Банк хранит счета по номерам: поле private Map<String, BankAccount> accounts, номер — строка вроде "40817-001". Методы:

  1. openAccount(String number, BankAccount account) — открыть счёт. Если номер уже занят — исключение. Номер не может быть пустым или null.
  2. BankAccount findAccount(String number) — найти счёт. Если нет — исключение со своим понятным сообщением, а не null и не NullPointerException. Своё ли исключение или стандартное — реши сам.
  3. transfer(String fromNumber, String toNumber, int amount) — перевод по номерам. Используй findAccount и уже готовый transferTo.
  4. int totalBalance() — сумма балансов всех счетов банка.

Шаг 2. Отчёты

  1. Set<String> owners() — все владельцы без повторов. У одного человека может быть несколько счетов.
  2. Map<String, Integer> balanceByOwner() — владелец → сумма по всем его счетам. Подсказка: приём «подсчёт» из раздела 4.
  3. Map<String, List<BankAccount>> accountsByOwner() — владелец → список его счетов. Подумай: что делать, когда у владельца встречается первый счёт и списка для него ещё нет?

Методы возвращают новые коллекции, а не поле accounts. Подумай, почему опасно вернуть наружу само поле (вспомни урок 3 и урок 2 про ссылки).

Шаг 3. Самопроверки в Main

Напиши в Main вспомогательный метод static void check(String name, boolean condition), который печатает ОК: name или ОШИБКА: name. Открой 4–5 счетов (у кого-то из владельцев — два, один накопительный) и проверь через check:

  1. owners().size() равен числу разных владельцев;
  2. balanceByOwner() для владельца с двумя счетами равен сумме двух балансов;
  3. totalBalance() не изменился после перевода между счетами банка;
  4. открытие счёта с занятым номером бросает исключение (флажок thrown, как в уроке 6);
  5. findAccount несуществующего номера бросает исключение.

Проверки пиши по заданию, до запуска. Если какая-то упала — сначала разберись, кто неправ: код или проверка.
