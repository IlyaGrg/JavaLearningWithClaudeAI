Зачем это backend-разработчику

В уроке 1 корзина была массивом int[]: цены есть, а названий товаров нет. Можно завести второй массив String[] names и следить, чтобы индексы совпадали… Но стоит отсортировать один массив и забыть про второй — и «Чай» начнёт стоить как ноутбук.

В настоящем backend всё — объекты: Order, Client, Account, Payment. В Spring Boot строка таблицы базы данных превращается в объект класса, JSON из запроса — тоже в объект. Через полгода ты будешь писать такие классы каждый день. Начинаем с одного: Product.

1. Класс — чертёж, объект — вещь по чертежу

Класс описывает, какие данные есть у товара (поля) и что с ними можно делать (методы). Объект — конкретный товар, созданный по этому описанию: «Чай за 250», «Кофе за 400». Класс один, объектов сколько угодно.

В Python ты это уже видел:

Python

class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def print_info(self):
        print(f"{self.name}: {self.price}")

tea = Product("Чай", 250)
tea.print_info()

Java

public class Product {
    String name;
    int price;

    Product(String name, int price) {
        this.name = name;
        this.price = price;
    }

    void printInfo() {
        System.out.println(name + ": " + price);
    }
}
// в main:
Product tea = new Product("Чай", 250);
tea.printInfo();

Четыре отличия, которые надо запомнить:

  1. Поля объявляются заранее, с типами, прямо в теле класса. В Python атрибуты появляются в __init__, а в Java у класса есть фиксированный список полей, и компилятор его проверяет.
  2. Конструктор вместо __init__: метод с именем класса и без типа результата (даже без void). — Oracle: Providing Constructors
  3. this вместо self, и его не пишут в параметрах: Java передаёт его сама.
  4. Объект создаётся через new.

2. Полный код с разбором каждой строки

Это два файла в одном пакете. Создай в IntelliJ папку src/lesson0002, в ней классы Product и Main, перепиши код руками и запусти Main.

src/lesson0002/Product.java

package lesson0002;
Пакет, как в уроке 1. Оба класса в одном пакете, поэтому видят друг друга без import.
public class Product {
Объявляем новый тип данных Product. Теперь можно писать Product x так же, как int x или String x. Класс public должен лежать в файле с тем же именем: Product.java.
String name;
Поле — переменная, которая есть у каждого объекта своя. У чая своё name, у кофе своё.
int price;
Ещё одно поле.
Product(String name, int price) {
Конструктор. Вызывается один раз, в момент new. Его задача — заполнить поля нового объекта.
this.name = name;
Параметр называется так же, как поле, и заслоняет его: просто name здесь — параметр. this.name — поле этого объекта. Читается: «в поле name этого объекта положи значение параметра name». Oracle: Using the this Keyword
this.price = price;
То же для цены.
}
Конструктор ничего не возвращает: результат new — сам готовый объект.
int priceWithDiscount(int percent) {
Метод объекта (не static). Он работает с данными конкретного товара, у которого его вызвали.
return price - price * percent / 100;
Здесь price без this: параметра с таким именем нет, значит это поле объекта. Java сама понимает, что это this.price.
}
Метод не меняет цену, а только возвращает расчёт. Объект остаётся прежним.
void printInfo() {
Ещё один метод объекта. Параметров нет: всё нужное уже лежит в полях.
System.out.println(name + ": " + price + " руб.");
Печатает данные того объекта, у которого вызвали метод.
}
}
Конец класса. Метода main здесь нет, и это нормально: Product — описание товара, а не программа.

src/lesson0002/Main.java

package lesson0002;
public class Main {
Класс-программа с точкой входа.
public static void main(String[] args) {
Product tea = new Product("Чай", 250);
new выделяет память под новый объект и вызывает конструктор с аргументами "Чай", 250. В tea кладётся ссылка на этот объект, как было с массивами.
Product coffee = new Product("Кофе", 400);
Второй, совершенно независимый объект по тому же чертежу.
tea.printInfo();
Точка означает «у этого объекта». Внутри метода this будет указывать на tea. Печатает Чай: 250 руб.
System.out.println(coffee.priceWithDiscount(10));
this = coffee, считаем 400 − 40. Печатает 360.
coffee.price = 380;
К полю тоже обращаются через точку. Меняется цена только кофе, у чая по-прежнему 250.
coffee.printInfo();
Печатает Кофе: 380 руб.
}
}

3. Объект живёт отдельно, в переменной — ссылка

Всё, что ты понял про массивы в уроке 1, работает и для объектов. Переменная хранит не товар, а ссылку на него:

Product a = new Product("Чай", 100);
Product b = a;          // копируется ССЫЛКА, нового объекта не появилось
b.price = 50;
System.out.println(a.price);   // 50

То же происходит при передаче объекта в метод: метод получает копию ссылки и может менять поля общего объекта. А p = new Product(...) внутри метода, как и с массивом, снаружи ничего не изменит.

Если ссылки нет: null

Ссылочная переменная может не указывать ни на какой объект. Это значение null (как None в Python). Вызов метода у null роняет программу:

Product p = null;
p.printInfo();
// NullPointerException: Cannot invoke "lesson0002.Product.printInfo()" because "p" is null

Это самое частое исключение в Java-проектах. Java 21 хотя бы пишет, какая переменная оказалась null, — читай текст ошибки целиком.

4. Что будет, если чего-то не написать

Поле не заполнено → значение по умолчанию

Добавим в Product поле int quantity;, но конструктор его не трогает. Тогда new Product("Чай", 100).quantity равно 0. Поля получают значения по умолчанию: 0 для чисел, false для boolean, null для ссылок (String, массивы, объекты). Локальные переменные внутри методов значения по умолчанию не получают: без присваивания будет ошибка компиляции. — Oracle: Primitive Data Types, Default Values

Конструктор не написан → компилятор добавит пустой

Если в классе нет ни одного конструктора, компилятор сам добавит конструктор без параметров, и new Product() заработает (все поля будут по умолчанию). Но как только ты написал свой конструктор, пустой больше не добавляется:

new Product();
// error: constructor Product in class Product cannot be applied to given types;

Это удобно: нельзя создать товар без названия и цены, если ты так решил. Конструкторов можно написать несколько — это та же перегрузка, что в уроке 1. — Oracle: Providing Constructors

5. Наконец-то: что значит static

В уроке 1 правило было «пиши static, если вызываешь из main». Теперь можно объяснить, откуда оно взялось.

  • Метод объекта (без static) работает с конкретным объектом. Его вызывают через объект: tea.printInfo(). Внутри есть this.
  • Статический метод принадлежит классу целиком, а не какому-то объекту. Его вызывают через имя класса: Math.max(3, 7), Arrays.toString(arr). Внутри нет this: нет объекта, на который он мог бы указывать.

main — статический: JVM запускает программу, ещё не создав ни одного объекта. Поэтому из main напрямую можно вызвать только другие static-методы. Метод объекта требует объект: сначала new, потом точка.

public class Shop {
    int count = 0;                        // поле объекта
    public static void main(String[] args) {
        count++;   // error: non-static variable count cannot be referenced from a static context
    }
}

Ту же ошибку для методов ты видел в справочнике урока 1. Теперь понятно: у main нет объекта, чьё count увеличивать. — Oracle: Understanding Class Members: «class methods cannot use the this keyword as there is no instance for this to refer to»

Как выбрать. Метод работает с полями объекта (цена этого товара)? Тогда это метод объекта. Метод нужен для общего расчёта над тем, что передали в параметрах (сумма корзины, максимум в списке)? Тогда можно static.

А что такое public?

Это модификатор доступа: кто может видеть класс, поле или метод. public — видно всем; без модификатора — только внутри своего пакета. Сейчас поля Product открыты, и любой может написать tea.price = -1000. Как это запретить и почему в банке это обязательно — тема урока 3 (инкапсуляция).

6. Проверь себя

Без подглядывания вверх. Ошибся — перечитай нужный раздел, это нормально.

1. Что напечатает программа? 
Product a = new Product("Чай", 100);
Product b = a;
b.price = 50;
System.out.println(a.price);

b = a копирует ссылку, объект один. Изменение через b видно через a.

2. В Product есть только конструктор Product(String name, int price). Какая строка не скомпилируется?

Ты написал свой конструктор, поэтому пустой компилятор не добавляет. Пустая строка и −1 компилятору не мешают: это корректные String и int. Запрещать их будем в уроке 3.

3. Поле int quantity; не заполняется в конструкторе. Чему равно new Product("Чай", 100).quantity?

Числовые поля по умолчанию равны нулю. null бывает только у ссылочных типов, а None есть только в Python.

4. Почему не компилируется count++ в main, если count — поле без static?

Поле объекта существует только внутри объекта. У main объекта нет, поэтому непонятно, чьё count увеличивать.

5. Повторение урока 1 на объектах. Что напечатает программа? 
static void rename(Product p)  { p.name = "Кофе"; }
static void replace(Product p) { p = new Product("Сок", 10); }
// в main:
Product x = new Product("Чай", 100);
rename(x);
replace(x);
System.out.println(x.name);

rename меняет поле общего объекта, и это видно снаружи. replace перезаписывает только свою копию ссылки, поэтому x по-прежнему указывает на тот же объект, уже с именем «Кофе».
