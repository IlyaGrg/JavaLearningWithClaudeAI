Урок 0012 · Java Core · ~90 минут + домашка

Stream API: описать, что нужно, а не как перебирать

После этого урока ты сможешь заменить циклы «отфильтруй — преобразуй — посчитай» цепочкой из трёх строк, сгруппировать счета одной командой и знать две ловушки, на которых спотыкаются на собеседованиях.

Зачем этот урок для backend. В Spring-сервисе типичный метод — «взять сущности из репозитория, отфильтровать, превратить в ответ для клиента». Это почти всегда стрим: repository.findAll().stream().filter(...).map(...).toList(). Stream API — одна из самых частых тем на собеседовании junior Java.

Разминка

1. Урок 11: чему равно BankAccount::getOwner?

Лямбде acc -> acc.getOwner(). Это Function<BankAccount, String>: из счёта получить строку. Сегодня такие функции будут в каждой строке.

2. Урок 11: проверка «каждый найденный счёт принадлежит Ilya» прошла на сломанном findAccounts. Почему?

Метод вернул пустой список. Цикл не выполнился ни разу, flag остался true. «Все элементы пустого списка подходят» — формально правда. Запомни это: сегодня встретишь то же самое в виде метода allMatch.

3. Урок 7: что будет, если удалить элемент из списка внутри for-each?

ConcurrentModificationException. Решение из урока 11 — removeIf. Стримы вообще не меняют исходную коллекцию — они строят новую.

1. От цикла к конвейеру

Твой totalBalance:

int totalSum = 0;
for (BankAccount user : accounts.findAll()) {
    totalSum += user.getBalance();
}
return totalSum;

Ты описываешь как: заведи переменную, перебери, прибавь. Со стримом описываешь что: «балансы всех счетов, сложить»:

return accounts.findAll().stream()
        .mapToInt(BankAccount::getBalance)
        .sum();

Стрим — это конвейер (Oracle: Aggregate Operations). Элементы коллекции едут по нему по одному, на каждом участке с ними что-то делают:

.stream()
Источник. Из коллекции получаем стрим. Сама коллекция не меняется.
.filter(...), .map(...)
Промежуточные операции. Возвращают новый стрим, их можно нанизывать сколько угодно.
.sum(), .toList(), .count()
Терминальная операция. Запускает конвейер и выдаёт результат: число, список, мапу. После неё стрим закончился.

2. Основные операции

Проверено на счетах Ilya 123 123, Valeria 100 000, Ilya 100 000, Anna 0:

filter — оставить подходящие

Принимает Predicate — как твой findAccounts:

accounts.stream()
        .filter(acc -> acc.getBalance() > 101_000)
        .toList();                              // [Ilya: 123123]

Весь твой findAccounts — это одна такая строка.

map — превратить каждый элемент

Принимает Function: из счёта — что-то другое:

accounts.stream()
        .filter(acc -> acc.getBalance() >= 100_000)
        .map(BankAccount::getOwner)             // счёт → имя
        .distinct()                             // убрать повторы
        .sorted()                               // по алфавиту
        .toList();                              // [Ilya, Valeria]

Читай сверху вниз: «счета от 100 000 → их владельцы → без повторов → по алфавиту → в список». Цикл с Set и сортировкой занял бы строк восемь.

mapToInt — когда нужны числа

map(BankAccount::getBalance) дал бы стрим Integer — с упаковкой каждого числа. mapToInt даёт IntStream из примитивов, а у него есть sum(), max(), average():

accounts.stream().mapToInt(BankAccount::getBalance).sum();   // 323123

Терминальные операции

ОперацияРезультатПример
toList()новый список (неизменяемый!)см. выше
count()long — сколько.filter(acc -> acc.getOwner().equals("Ilya")).count() → 2
anyMatch / allMatch / noneMatchboolean.allMatch(acc -> acc.getBalance() >= 0) → true
collect(Collectors.toSet())Set.map(BankAccount::getOwner).collect(Collectors.toSet())
max(comparator), findFirst()Optional — «может быть, есть»Optional[Ilya: 123123] или Optional.empty

Optional — коробка, в которой результат может быть, а может не быть (если стрим пуст). Подробно — в уроке 13, пока просто узнавай его в выводе.

sorted и limit — «топ»

accounts.stream()
        .sorted(Comparator.comparingInt(BankAccount::getBalance).reversed())
        .limit(2)
        .toList();                              // [Ilya: 123123, Valeria: 100000]

Компаратор из урока 11 работает в стримах без изменений.

3. Группировка: groupingBy

Твой accountsByOwner с computeIfAbsent — это одна терминальная операция (Collectors):

accounts.stream()
        .collect(Collectors.groupingBy(BankAccount::getOwner));
// {Anna=[Anna: 0], Ilya=[Ilya: 123123, Ilya: 100000], Valeria=[Valeria: 100000]}

А balanceByOwner с merge — та же группировка, только вместо списка счетов в каждой группе считается сумма:

accounts.stream()
        .collect(Collectors.groupingBy(BankAccount::getOwner,
                                       Collectors.summingInt(BankAccount::getBalance)));
// {Anna=0, Ilya=223123, Valeria=100000}

Первый аргумент — «по чему группировать», второй — «что делать с каждой группой». Без второго группа — это список.

4. Три ловушки

Ловушка 1: allMatch на пустом стриме — true

List<BankAccount> empty = List.of();
empty.stream().allMatch(acc -> acc.getBalance() > 1_000_000);   // true

Это твоя ошибка из урока 11, встроенная в стандартную библиотеку. «Все счета миллионеров?» — у пустого списка нет ни одного счёта, который это опровергнет, значит true. Так устроена логика (в документации так и написано: «If the stream is empty then true is returned»). Поэтому проверка через allMatch без проверки размера — та же дыра, что твой flag.

Ловушка 2: стрим одноразовый

Stream<BankAccount> s = accounts.stream();
s.count();
s.count();
// java.lang.IllegalStateException: stream has already been operated upon or closed

Стрим — не коллекция, а конвейер, который проезжают один раз. Нужно ещё раз — вызови accounts.stream() заново. Хранить стрим в поле или переменной почти никогда не нужно.

Ловушка 3: toList() даёт неизменяемый список

List<BankAccount> list = accounts.stream().toList();
list.add(...);   // java.lang.UnsupportedOperationException

Как List.of из урока 7. Обычно это хорошо: метод банка возвращает список, и вызывающий не сможет его испортить. Если список нужно менять — collect(Collectors.toList()), он даёт изменяемый ArrayList.

И одна особенность: стрим ленивый

Stream<BankAccount> s = accounts.stream()
        .filter(acc -> { System.out.println("проверяю " + acc); return acc.getBalance() > 0; });
System.out.println("стрим создан");    // напечатается только это
s.count();                             // а вот теперь — четыре «проверяю …» и 3

Промежуточные операции ничего не делают, пока нет терминальной. Отсюда правило: в filter и map не должно быть побочных эффектов — печати, изменения полей, записи в коллекции. Они нужны только чтобы вычислить результат.

Частые вопросы

Стрим всегда лучше цикла?

Нет. Стрим хорош для «отфильтруй — преобразуй — собери». Если в цикле сложная логика с break, исключениями, изменением нескольких переменных — цикл честнее. Твой transfer никто не стал бы переписывать на стрим.

А forEach у стрима — то же, что цикл?

Почти. Но если внутри forEach ты складываешь во внешнюю переменную или коллекцию — это сигнал, что нужна другая терминальная операция: sum, toList, groupingBy. Помнишь ошибку effectively final из урока 11? Она как раз об этом.

Стримы быстрее циклов?

Нет, обычно чуть медленнее или так же. Выбирают их ради читаемости, а не скорости. Бывают «параллельные стримы» (parallelStream()), но без серьёзной причины их не используют — это тема для опытных.

Проверь себя

1. Что сделает строка accounts.stream().filter(acc -> acc.getBalance() > 0); сама по себе?

Стрим ленивый: filter только описывает участок конвейера. Запустит его терминальная операция — toList, count, sum. И исходный список стрим не меняет никогда.

2. Что вернёт accounts.stream().mapToInt(BankAccount::getBalance).sum()?

mapToInt превращает каждый счёт в его баланс, sum складывает. Это весь твой totalBalance.

3. Список пуст. Что вернёт list.stream().allMatch(acc -> acc.getOwner().equals("Ilya"))?

Для пустого стрима allMatch — true. Это ловушка твоего flag из урока 11. Проверяй размер отдельно.

4. Stream s = list.stream(); s.count(); s.count(); Что будет на второй count?

Стрим одноразовый: stream has already been operated upon or closed. Нужен ещё раз — list.stream() заново.

5. List<BankAccount> l = accounts.stream().toList(); l.add(acc); Что будет?

toList() возвращает неизменяемый список, как List.of. Изменяемый — через collect(Collectors.toList()).

Шаг 1. Ветка и копия

git status чистый → git switch -c feature/streams → src/lesson0011 в src/lesson0012 (без EXPERIMENTS.md), package, 28 проверок ОК, коммит.

Шаг 2. Сначала недостающие проверки

Ты будешь переписывать totalBalance и owners, а проверок для них нет. Добавь на текущий код: точная сумма балансов тестового банка (посчитай руками); owners() содержит ровно нужные имена и нужного размера. ОК → коммит. Это тот же шаг 3 из урока 11 — ты его уже умеешь.

Шаг 3. Переписать банк на стримы

Каждый метод — отдельный коммит, после каждого — все проверки ОК:

  1. totalBalance — через mapToInt и sum;
  2. owners — через map и Collectors.toSet();
  3. findAccounts — через filter;
  4. sortedByOwner, sortedByBalanceDesc — через sorted;
  5. accountsByOwner и balanceByOwner — через groupingBy.

Внимание к пункту 4: у тебя есть проверка «список банка не изменился после сортировки»? Если нет — самое время. И подумай: что изменилось бы, если бы ты вернул toList(), а вызывающий код попробовал бы его отсортировать?

Шаг 4. Два новых метода

  • List<String> richOwners(int minBalance) — имена владельцев, у которых хотя бы один счёт не меньше minBalance, без повторов, по алфавиту;
  • long countAccounts(Predicate<BankAccount> filter) — сколько счетов подходит.

Проверки — с точными ожиданиями, посчитанными руками до запуска. Для richOwners подбери такой порог, при котором у Ilya подходит только один из двух счетов — это проверит distinct.

Шаг 5. Проверки тоже на стримы

Перепиши проверки findAccounts из урока 11 (цикл с flag) через allMatch. Затем сломай findAccounts на «всегда пустой список» и посмотри: поймает ли твоя проверка? Если нет — почему (ловушка 1) и как исправить. Запиши ответ в src/lesson0012/EXPERIMENTS.md.

Шаг 6. Эксперименты — в ветке experiment/stream-traps

  1. Вызови две терминальные операции на одном стриме.
  2. Получи список через toList() и попробуй добавить в него счёт.
  3. Поставь System.out.println внутрь filter, но не вызывай терминальную операцию. Что напечатается? Потом добавь count().

Вывод — в терминале. Потом git switch feature/streams, запиши в EXPERIMENTS.md вывод и объяснение своими словами, коммит. Ветку эксперимента — -D.
